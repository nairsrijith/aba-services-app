API Documentation

This page documents the JSON API endpoints available under /api. Access is restricted to authenticated users with the admin or super role.

Authentication

Generate a bearer token using the API management tools available under the Settings page.

Warning: The token will be shown only once. Save it immediately after creation.

If you prefer curl, use the POST example below.

curl -X POST '{{ url_for('api.auth_token', _external=True) }}' \
  -H 'Content-Type: application/json' \
  -d '{"email":"{{ current_user.email }}","password":"YourPassword","expires_in":86400}'

If the credentials are valid, the response contains a token you must send on all API requests:

{
  "token": "eyJ...",
  "expires_in": 86400
}

Use the token header like this:

Authorization: Bearer <token>
Service accounts & automation tokens

Admins may create named service accounts and generate long-lived automation tokens tied to those accounts.

Example API calls
curl -X POST '{{ url_for('api.create_service_account', _external=True) }}' \
  -H 'Content-Type: application/json' \
  -d '{"email":"{{ current_user.email }}","password":"YourPassword","name":"billing-bot","description":"Invoice automation"}'
curl -X POST '{{ url_for('api.create_automation_token', _external=True) }}' \
  -H 'Content-Type: application/json' \
  -d '{"email":"{{ current_user.email }}","password":"YourPassword","service_account_name":"billing-bot","expires_in":15552000}'

Response includes the raw automation token and service account metadata.

General Rules
  • All endpoints are mounted under /api.
  • Requests use JSON bodies for POST and PUT.
  • Responses use JSON with standard HTTP status codes.
  • Admin and super users may access protected resources.
Users

Admin users may manage employee accounts via these endpoints.

List users
curl '{{ url_for('api.list_users', _external=True) }}' \
  -H 'Authorization: Bearer <token>'
Create user
curl -X POST '{{ url_for('api.create_user', _external=True) }}' \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{
    "firstname":"Jane",
    "lastname":"Doe",
    "position":"Therapist",
    "email":"jane.doe@example.com",
    "cell":"5551234567",
    "user_type":"therapist"
  }'
Get user
curl '{{ url_for('api.get_user', user_id=1, _external=True) }}' \
  -H 'Authorization: Bearer <token>'
Clients

Client endpoints provide CRUD operations for clients.

Create client
curl -X POST '{{ url_for('api.create_client', _external=True) }}' \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{
    "firstname":"Test",
    "lastname":"Client",
    "dob":"2010-01-01",
    "gender":"Male",
    "address1":"100 Test Ave",
    "city":"Testville",
    "state":"TX",
    "zipcode":"75001"
  }'
Update client
curl -X PUT '{{ url_for('api.update_client', client_id=1, _external=True) }}' \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"city":"New City", "zipcode":"75002"}'
Invoices

Invoices are created from client interventions and optional mileage records.

Create invoice
curl -X POST '{{ url_for('api.create_invoice', _external=True) }}' \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{
    "client_id": 1,
    "date_from":"2026-06-01",
    "date_to":"2026-06-30",
    "selected_interventions":[10],
    "payby_date":"2026-07-15",
    "status":"Draft"
  }'
Update invoice
curl -X PUT '{{ url_for('api.update_invoice', invoice_number='INV2026060001', _external=True) }}' \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"status":"Paid"}'
Payroll
Create pay rate
curl -X POST '{{ url_for('api.create_payrate', _external=True) }}' \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{
    "employee_id": 2,
    "client_id": 1,
    "rate": 75.0,
    "effective_date":"2026-06-15"
  }'
Create paystub
curl -X POST '{{ url_for('api.create_paystub', _external=True) }}' \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{
    "employee_id": 2,
    "period_start":"2026-06-01",
    "period_end":"2026-06-15",
    "generated_date":"2026-06-15",
    "total_hours": 8.0,
    "total_amount": 600.0,
    "items":[{"intervention_id": 10, "client_id": 1, "rate": 75.0, "hours": 8.0, "amount": 600.0}]
  }'
Reports

Report endpoints return filtered JSON results for employees, clients, sessions, invoices, and paystubs.

Employee report
curl '{{ url_for('api.employees_report', _external=True) }}?active=active' \
  -H 'Authorization: Bearer <token>'
Client report
curl '{{ url_for('api.clients_report', _external=True) }}?state=TX' \
  -H 'Authorization: Bearer <token>'
Session report
curl '{{ url_for('api.sessions_report', _external=True) }}?start_date=2026-06-01&end_date=2026-06-30' \
  -H 'Authorization: Bearer <token>'
Web route proxy

The proxy endpoint mirrors any browser URL under /api/ via server-side internal dispatch.

curl '{{ url_for('api.proxy', path='clients', _external=True) }}' \
  -H 'Authorization: Bearer <token>'

This returns JSON with the original HTML content and status code.
